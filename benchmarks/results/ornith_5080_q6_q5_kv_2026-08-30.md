# Ornith RTX 5080 Q6-K/Q5-V KV validation

Date: 2026-08-30  
Host: NVIDIA GeForce RTX 5080 (sm_120), 16 GiB, WSL  
Model: Ornith-1.5-35B-A3B GGUF Q6_K

FreeToken now exposes a second deliberately narrow asymmetric KV lane: GGML Q6_0
keys plus GGML Q5_0 values. Q5 uses a cache-native contiguous low-nibble/high-bit
layout, while keeping GGML Q5_0's signed-extreme scale and codes. Q6/Q5 is an
explicit compact/long-context tier; Q8/Q6 remains the high-fidelity tier.

The production host reserve stayed at 3 GiB. Live comparisons used
`FREETOKEN_PIN_BUDGET_GB=20`, the established Q6 deployment profile, and otherwise
identical 8K prefill chunks, 32K KV growth steps, five linear-state slots, pageable
GPU experts, and LFU residency.

## Correctness gates

- CPU Q5 reference quantize/dequantize and exact cache-native layout checks passed.
- GPU Q6-K/Q5-V store matched the reference payload and scales exactly.
- Paged, split-K decode, and split extend attention matched their dequantized BF16
  oracles. The benchmark repeated the oracle before every timed case.
- Static and growable MHA pools stored, rebuilt, committed, and decommitted the
  independent Q6/Q5 slabs correctly.
- The exact 65,536-token gate used a 65,408-token prompt plus 128 output allowance,
  crossed the 32K -> 64K CUDA-VMM boundary, recovered passcode `5663623`, and
  returned a coherent explicit answer.
- 132 focused kernel, pool, config, and benchmark tests passed.

## Memory and residency

Q6_0 and Q5_0 consume 6.5 and 5.5 bits/value including their fp16 scales: 12 bits
per K/V scalar pair versus 15 for Q8/Q6, a 20% logical reduction.

| 64K gate | Q8-K/Q6-V | Q6-K/Q5-V | Change |
|---|---:|---:|---:|
| Logical KV | 0.59 GiB | **0.47 GiB** | -20% |
| Growable physical ceiling | 0.66 GiB | **0.55 GiB** | -0.11 GiB |
| Initial expert slots | 4,674 | **4,698** | +24 |
| Final expert slots | 4,440 | **4,489** | +49 |

At 1,048,576 tokens the logical Q6/Q5 payload is 7.50 GiB, versus 9.375 GiB for
Q8/Q6. This is arithmetic, not a measured 1M Q6/Q5 run.

## Isolated attention

The Blackwell decode sweep selected 128 splits, a 32-token KV tile, and four warps.
The cached-prefix extend sweep retained the 64x32 tile but used eight warps and two
stages. A 16-token tile failed the numerical oracle and a 64-token extend tile
exceeded the card's per-block shared-memory budget, so neither was admitted.

| Context | Q8-K/Q6-V | Q6-K/Q5-V | Q6/Q5 change |
|---:|---:|---:|---:|
| 8K | 0.0311 ms/layer | 0.0412 ms/layer | +32.5% |
| 32K | 0.0720 | 0.0841 | +16.8% |
| 64K | 0.1272 | 0.1376 | +8.2% |
| 131K | 0.2584 | **0.2563** | -0.8% |
| 262K | 0.4942 | **0.4795** | -3.0% |

The short-context percentage looks large because it is only tens of microseconds per
full-attention layer. Q6/Q5 crosses over near 131K as reduced KV traffic begins to
outweigh its additional unpack instructions.

For cached-prefix extend, after tuning Q6/Q5 remained about 5-8% slower than Q8/Q6
across the tested 2K-32K prefixes and 256-8K chunks. The initial untuned kernel was
35-41% slower and was rejected.

## Live serving comparison

The paired exact-64K runs are the final performance comparison:

| Exact 65,408 + 128 gate | Q8-K/Q6-V | Q6-K/Q5-V | Change |
|---|---:|---:|---:|
| End-to-end prefill | 652.85 tok/s | **663.84 tok/s** | +1.7% |
| Engine average prefill | 640.52 tok/s | **653.14 tok/s** | +2.0% |
| Final-chunk instant prefill | **670.49 tok/s** | 623.11 tok/s | -7.1% |
| Decode | **43.19 tok/s** | 40.17 tok/s | -7.0% |
| Retrieval/coherence | PASS | PASS | — |

At the shorter 32,640 + 128 gate, Q6/Q5 averaged 643.45 tok/s prefill versus
587.74 for Q8/Q6, while decode was 43.41 versus 43.87 tok/s (-1.0%). The exact 64K
gate is the conservative result to use when planning this tier.

### Exact 524,288-token comparison

The final long-context comparison used the same Q6_K model and exactly 524,160
prompt tokens plus 128 output-token capacity. All three runs used static YaRN factor
2 from the native 262,144-token context, 8,192-token prefill chunks, 131,072-token
KV growth steps, five linear-state slots, LFU, `--memory-ratio 0.97`, pageable GPU
experts, `FREETOKEN_PIN_BUDGET_GB=20`, and the unchanged 3 GiB host reserve. Each
run selected the same ten pageable MoE layers.

| Exact 524,160 + 128 gate | Q8-K/Q8-V | Q8-K/Q6-V | Q6-K/Q5-V |
|---|---:|---:|---:|
| Logical KV | 5.31 GiB | 4.69 GiB | **3.75 GiB** |
| Growable physical ceiling | 5.39 GiB | 4.77 GiB | **3.83 GiB** |
| Final expert slots | 2,434 | 2,694 | **3,084** |
| Prompt wall time | **1,409.53 s** | 1,459.00 s | 1,423.63 s |
| End-to-end prefill | **371.87 tok/s** | 359.26 tok/s | 368.19 tok/s |
| Engine average prefill | **371.37 tok/s** | 358.93 tok/s | 367.72 tok/s |
| Last full 8K instant prefill | **262.91 tok/s** | 244.34 tok/s | 260.43 tok/s |
| Final 8,064-token instant prefill | 246.79 tok/s | 232.02 tok/s | **262.11 tok/s** |
| Decode | 27.70 tok/s | 28.78 tok/s | **28.97 tok/s** |
| Retrieval/coherence | PASS | PASS | PASS |

For one 524K session, Q8/Q8 and Q6/Q5 are effectively tied: Q6/Q5 gives up 0.98%
engine-average prefill and 0.94% on the last full chunk, while saving 1.56 GiB of
physical KV and retaining 650 more experts. Q8/Q8 is therefore the precision-first
single-session choice; Q6/Q5 is the capacity-first choice for concurrent/growing
sessions. Q8/Q6 saved 0.62 GiB versus Q8/Q8 but was 3.35% slower on average and
7.06% slower on the last full chunk in this run, so it has no compelling performance
advantage at this context size.

All three outputs recovered `5663623` and gave a coherent explicit answer before the
end-of-message marker. This retrieval gate detects gross inference corruption; it is
not a substitute for a multi-task quality evaluation of the lower-bit cache pairs.

## Decision

Q6/Q5 is accepted as an opt-in compact/long-context pair. It is not the default Q6
cache because its 64K decode and late-prefix prefill toll is measurable and published
Qwen-family KLD results place it below Q8/Q6 in fidelity. It becomes mechanically
more attractive beyond roughly 131K and frees 1.875 GiB of logical KV at 1M, where
both attention bandwidth and expert residency favor it.

```bash
FREETOKEN_PIN_BUDGET_GB=20 ft serve \
  --model /path/to/Ornith-1.5-35B-Q6_K.gguf \
  --attention-backend triton --moe-backend offload --moe-cache-auto \
  --moe-pageable-gpu --host-ram-reserve-gb 3 \
  --kv-cache-dtype-k q6_0 --kv-cache-dtype-v q5_0 \
  --num-tokens 262144 --kv-grow-step-tokens 32768
```

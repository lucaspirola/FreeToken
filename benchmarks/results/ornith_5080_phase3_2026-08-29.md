# Ornith RTX 5080 phase-3 benchmark

Date: 2026-08-29  
Host: NVIDIA GeForce RTX 5080 (sm_120), 16 GiB, WSL  
Stack: Torch 2.11, CUDA 13.0, Triton 3.6

Both serving configurations reserved the full 262,144-token KV pool with one
running request, LFU expert caching, 0.97 memory ratio, 8,192-token prefill
chunks, and the Triton attention backend.

| Gate | Q4_K_M + INT4 KV | Q6_K + Q8_0 KV |
|---|---:|---:|
| Warm decode before | 164.51 tok/s | 125.64 tok/s |
| Warm decode after shared-MMVQ tuning | 168.08 tok/s (+2.17%) | 128.52 tok/s (+2.29%) |
| 8K cold prefill, prior dense policy | 1259.52 tok/s | 528.14 tok/s |
| 8K cold prefill, accepted policy | 1259.52 tok/s (Q4 experiment rejected) | 623.31 tok/s (+18.0%) |

The decode A/B used identical greedy AIME prompts. Q4 retained output hash
`1e7fc3a18713`; Q6 retained `336e501be499`. The prefill acceptance gate used
the built-in deterministic needle workload. Every retained and control leg
recovered `5663623` and returned a coherent explicit answer.

Accepted changes:

- Four output-row warps for fused routed+shared Q4_K/Q6_K decode MMVQ on sm_120.
- Grouped int8-MMA MoE crossover lowered from 320 to 272 tokens (all three Ornith
  projections win at 272; DP4A still wins at 256).
- Exact sm_120 Q6_K dense bands for shared and output projections; large fused
  QKV projections keep uncapped int8-MMA.

Rejected screens:

- Q4 dense dequant bands: isolated kernels won, but live overlapped prefill lost
  8.7%, so the original uncapped MMA policy remains.
- 128-way attention split-K, alternate tile/warp geometries, and a Q8 native
  integer-score path: none beat the existing 64-split launch.
- Wider PCIe gather grids: the current launch already sustained about 50-52 GB/s
  on this host and alternatives were tied.

Validation:

- 147 focused GGUF dispatch, quantization, MMA, model, and benchmark tests passed.
- Ruff and `git diff --check` passed.
- The full non-slow suite completed with 1,622 passed and 9 skipped. Its 8
  failures and 6 setup errors are unrelated documented clean-main families
  (configuration-test drift, shared TP state, stale optional native extension,
  CUDA batch-copy support, and test-package import).

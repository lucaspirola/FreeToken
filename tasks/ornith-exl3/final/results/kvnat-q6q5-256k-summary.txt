## Summary of the main design decisions

The document describes serving two Nemcheckpoint families on FreeToken, and the design is held together by a few load-bearing choices:

**1. MoE experts live in host RAM, fetched over PCIe on demand (`offload`).** The NVFP4 expert banks (15.4 GiB on Lightning) are pinned in system memory and copied to the GPU only when routed. This trades steady PCIe bandwidth for the ability to fit a 120B-A12B / 30B-A3B model on a 16 GB card. The whole serving model is built around this being movement-bound: 74% of a 16-lane decode step is PCIe expert misses.

**2. The MoE GEMM backend is pinned to `triton`, overriding `auto`.** `auto` resolves to b12x (tensor-core) on this geometry, which the microbenchmarks and one soak show is slower end-to-end. Because the backend pins the on-GPU weight layout at bank-load time, you can't mix backends across prefill/decode, so this is a single global decision.

**3. Memory is planned to 100% of free VRAM, by owner decision.** `--memory-ratio` is no longer a tuning knob — it's fixed at 1.00, and the engine predicts headroom from config, measures the prefill transient, and fills the arena so exactly that is left free. Operators cannot tune it per host.

**4. Residency is on-demand, not timer-based.** Sessions spill to RAM/NVMe only when another request needs the slot; the resident session is never checkpointed while the queue is empty. Checkpoints survive restart via manifest + fingerprint matching, and a background look-ahead thread warms queued checkpoints from NVMe to RAM.

**5. Two very different serving modes.** Nemotron 3 Super is `single_stream_only` (one session, ~160 MiB Mamba state each, ~60 GiB host RAM). Lightning is 16-way concurrent (47 MiB state each). The 1M long-context profile collapses back to one resident session with spill.

**6. Speculative decoding (ngram) shipped, off by default**, greedy and single-stream in v1, with `--spec-ngram-n 8` / `--spec-draft-len 8`. Long context regresses, so the engine self-gates.

**7. Kernel work is driven by single-binary A/B** with byte-identical verification (`0.000e+00`): decode graph ladder made dense [1..16], MoE prefill GEMM fixed (per-block scale broadcast, native FP4 decode, A deinterleave), extend tile register-capped, decode launch grid scaled to the GPU.

The document is unusually honest about retractions and corrections, which is a strength I'll come back to.

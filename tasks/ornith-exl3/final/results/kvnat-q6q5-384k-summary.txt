**Architecture/Serving model:**

- Nemotron 3.5 Lightning (30B-A3B) is NOT single_stream_only: up to 16 concurrent requests because its state is only 47 MiB per slot
- Hybrid Mamba-2 / full-attention / latent-MoE architecture

**Expert cache policy:**
- LFU over LRU at high concurrency (16-way): LFU halves miss rate (99.6% → 51%) and gives 1.80× throughput
- Rule of thumb: LFU above ~15% miss rate, LRU below
- Fixed-capacity VMM arena for expert cache

- Growable KV via `--kv-grow-step-tokens` (but this has a documented problem — it costs the whole prefix cache)
- KV dtype triton attention backend required for quantized KV

**CUDA graphs:**
- Dense decode graph ladder `[1..16]` for offload-MoE models (padded rows route their own experts, so exact graphs matter)
- Sparse graphs waste because padding routes experts
- Graph set made dense to 16

**Launch profiles:**
- Default profile: single lane, `--max-running-requests 1 --linear-state-slots 13`
- 1M profile: one resident session, others queue/spill
- Session spill to RAM then NVMe

**Prefill:**
- `--max-prefill-length 8192` — chunk size is NOT a throughput lever
- Triton expert GEMM over b12x/marlin/flashinfer
- MoE prefill GEMM optimizations (per-block scale loading, A operand deinterleaving)

**Speculative decoding:**

- `--spec-ngram-n 8`, `--spec-draft-len 8` default
